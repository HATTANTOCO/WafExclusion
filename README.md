# WafExclusion for baserCMS 4

Webサーバーに導入されているWAF（SiteGuard Lite / ModSecurity）による管理画面操作時の403誤検知を防ぐため、**管理画面にログインして操作中の対象ユーザーのIPアドレスのみを一時的に動的バイパス**する baserCMS 4系（CakePHP 2系ベース）プラグインです。

---

## 主な特徴

* **SiteGuard Lite と ModSecurity の両方に1プラグインで対応**
  * 国内主要レンタルサーバー（ロリポップ！、エックスサーバー、さくらのレンタルサーバ、ヘテムル、CPI等）で採用されている **SiteGuard Lite（`mod_siteguard.c`）** と、Apache環境で広く利用される **ModSecurity（`mod_security2.c`）** の双方に対応しています。
  * 設定画面のラジオボタンでWAF種別を切り替えると、非選択側の旧設定を自動的に消去（パージ）したうえで、新しいWAF形式の除外ディレクティブへ即座に書き換えます。
* **配布パッケージ版・GitHubリポジトリDL版の両構造および公開ルート構成の自動判定**
  * 公式サイトの配布パッケージ版（インストールルート直下にファイルが展開されるフラット構成）および、GitHubリポジトリDL版・スマートインストール構成（`app/webroot/` ディレクトリが存在する構成）のどちらでも、サーバーの公開フォルダ設定に応じてWAFが最初に評価する対象 `.htaccess` を自動判定して書き込みます。
* **ログイン中の対象ユーザーIPアドレスのみを動的バイパス**
  * 許可されたユーザーグループに所属するユーザーが管理画面を開いている間のみ、対象の `.htaccess` に除外ディレクティブを自動追記します。
  * 固定IPを持たないリモートワークやモバイル回線（IPアドレスが頻繁に変わる環境）でも、ページ遷移やタブ復帰のたびに現在の接続元IPを自動検知して登録・リカバリーします。
* **サーバー環境診断ステータス＆安全ガード**
  * 設定画面で「現在の接続元IPアドレス」「書き込み対象ファイル（`.htaccess`）とその書き込み権限」を常時診断して表示します。
  * ModSecurity選択時は「Apacheバージョン（`2.4.26` 以上）」および「`mod_security2` 検出状況」を自動診断し、条件を満たさない環境での500エラーを防ぐ**自動判定モード**と、サーバー情報が隠蔽されている環境向けの**強制有効モード**を切り替えられます。
* **対象ユーザーグループの柔軟な制御**
  * 設定画面から、WAF自動バイパスを許可するユーザーグループをチェックボックスで選択できます（システム管理者グループはセキュリティおよび運用維持のため常に必須対象となります）。
* **ログアウト・無効化時の自動クリーンアップ（パージ）**
  * 管理画面から**ログアウト**した際、およびプラグイン管理画面から本プラグインを**無効化**した際に、対象の `.htaccess` から該当の除外ディレクティブを自動的に全消去します。
  * 設定画面の「WAF除外IPを全てクリア」ボタンから、過去に登録された不要なIPを一括リセットすることも可能です（クリア実行後、画面が自動リフレッシュされ、現在ログイン中のIPアドレスのみ再登録された状態をプレビューで即座に確認できます）。
* **挿入位置のカスタマイズ（マーカー対応）**
  * 書き込み対象となる `.htaccess` 内の任意の行に `# [WAF_EXCLUSION_MARKER]` と記述しておくと、その直下に除外ディレクティブを挿入します（未記述の場合はファイル先頭に挿入されます）。
* **管理画面URLの秘匿化（カスタムプレフィックス）・IPv4 / IPv6 に対応**
  * セキュリティ対策として管理画面のURLプレフィックスを変更している環境（`/admin` 以外）や、サブディレクトリ配下にインストールしている環境でも、エンドポイントURLを動的に解決して安全に動作します。IPv4 / IPv6 の双方に対応しています。

## 動作要件

* **baserCMS**: 4.x（CakePHP 2系ベース）
* **PHP**: 7.x 以上（PHP 8.x 対応）
* **Webサーバー / WAF**:
  * **SiteGuard Lite 利用時**: `mod_siteguard.c` が有効なApache環境（有効化直後から初期設定のまま利用可能）
  * **ModSecurity 利用時**: Apache 2.4.26 以上 + `mod_security2.c` が有効な環境（`<If "%{REMOTE_ADDR} == '...'">` ディレクティブを使用するため、Apache 2.4.26 以上が必要です）
* **サーバー環境の要件**:
  * **リバースプロキシ環境（Cloudflare等）でのご利用について**: リバースプロキシやCDNを経由している環境で本プラグインを正常に動作させるには、Webサーバー（Apache）側で `mod_remoteip` などのIP復元設定が正しく行われ、PHPの `$_SERVER['REMOTE_ADDR']` に「真の接続元クライアントIP」が格納されている必要があります。
* **ファイル権限**:
  * WAFの除外設定を書き込む対象 `.htaccess` にPHPからの書き込み権限があること
    * 配布パッケージ版（ルート直下構成）、またはGitHubリポジトリDL版で公開フォルダがインストールルートに設定されている環境：**`.htaccess`（baserCMSのインストールルート直下）**
    * GitHubリポジトリDL版で公開フォルダが `app/webroot/` に直接設定されている環境：**`app/webroot/.htaccess`（baserCMSのインストールルート配下の app/webroot 内）**
    * ※どちらのファイルが対象になるかはプラグインが自動判定し、設定画面の「サーバー環境診断ステータス」に表示されます。
  * 管理画面から設定を変更・保存する場合は `app/Plugin/WafExclusion/Config/setting.php` にも書き込み権限があること
  * **※セキュリティ上の注意**: パーミッションは **`604`（または `600` / `644`）** など所有者のみ書き込み可能な設定にし、**`606`・`666`・`777` 等の全ユーザー書き込み許可には絶対に設定しないでください。**

## インストール方法

1. 本リポジトリをダウンロード（または `git clone`）し、ディレクトリ名を **`WafExclusion`** にします。
2. baserCMS 4系の `app/Plugin/` ディレクトリ配下（`app/Plugin/WafExclusion/`）にアップロードします。
3. baserCMSの管理画面「設定」＞「プラグイン管理」を開き、**WafExclusion** の「インストール（有効化）」ボタンをクリックします。
   * 初期設定では「SiteGuard Lite」および「システム管理者グループ」が有効になっているため、有効化した直後から自動バイパスが動作します。

## 使い方

### 1. 初期設定と環境診断・WAF種別の選択
1. プラグイン一覧の「設定（歯車アイコン）」から設定画面を開きます。
   * `/admin/waf_exclusion/waf_exclusion/index`（※管理画面プレフィックスを変更している場合は読み替えてください）
2. 上部の「サーバー環境診断ステータス」で、**書き込み対象ファイル** とその**書き込み権限**が「書き込み可能」になっていることを確認します。
3. 「使用するWAF種別」で、ご利用中のサーバーに合わせて **SiteGuard Lite** または **ModSecurity** を選択します。
   * ModSecurityを選択した際、サーバー情報（`ServerTokens` 等）が隠蔽されていて環境診断ステータスが「待機中」になる場合は、「動作モード」を **「強制有効」** に切り替えて保存してください。
4. 「対象ユーザーグループ」から、WAF自動バイパスを許可したいグループにチェックを入れて「保存」をクリックします。

### 2. 自動バイパスの動作
* 対象グループに所属するユーザーが管理画面のページへアクセスすると、バックグラウンド通信により現在の接続元IPアドレスが対象の `.htaccess` へ自動的に書き込まれます。
* 書き込み成功後、設定画面のプレビュー欄には選択中のWAF種別に応じたディレクティブが表示されます。

#### SiteGuard Lite 選択時の出力例
```text
# --- WAF_EXCLUSION_START ---
<IfModule mod_siteguard.c>
  SiteGuard_User_ExcludeSig ip(203.0.113.10)
</IfModule>
# --- WAF_EXCLUSION_END ---
```

#### ModSecurity 選択時の出力例
```text
# --- WAF_EXCLUSION_START ---
<IfModule mod_security2.c>
  <If "%{REMOTE_ADDR} == '203.0.113.10'">
    SecFilterEngine Off
    SecRuleEngine Off
  </If>
</IfModule>
# --- WAF_EXCLUSION_END ---
```

### 3. 挿入位置の指定（マーカー配置の推奨位置）

記述順序の矛盾や他ディレクティブとの干渉を防ぐため、**書き込み対象となる `.htaccess`（設定画面の「サーバー環境診断ステータス」に表示されているファイル）** 内の安全な位置に、本プラグイン専用の挿入マーカーを記述することを推奨します。

```text
# [WAF_EXCLUSION_MARKER]
```

※マーカーを記述しない場合はファイルの先頭に自動挿入されます。

#### パターンA：`.htaccess`（baserCMSのインストールルート直下）が対象の場合
配布パッケージ版（ルート直下構成）、またはGitHubリポジトリDL版でドメインの公開フォルダが baserCMS のインストールルートに設定されている場合は、インストールルート直下の `.htaccess` 内の `RewriteEngine On` のすぐ下（または `<IfModule mod_rewrite.c>` の直前）にマーカーを配置してください。

```text
<IfModule mod_rewrite.c>
  RewriteEngine On

  # 本プラグイン用のマーカーをここに配置
  # [WAF_EXCLUSION_MARKER]

  RewriteBase /
  RewriteRule ^index\.php\$ - [L]
  ...
</IfModule>
```

#### パターンB：`app/webroot/.htaccess`（baserCMSのインストールルート配下の app/webroot 内）が対象の場合
GitHubリポジトリDL版（またはスマートインストール構成）でドメインの公開フォルダが `app/webroot/` に直接設定されている場合は、`app/webroot/.htaccess` 内の `<IfModule mod_rewrite.c>` の**直前**（または `RewriteEngine On` のすぐ下）にマーカーを配置してください。

```text
# [WAF_EXCLUSION_MARKER]

<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteRule ^(.*)\$ index.php [QSA,L]
</IfModule>
```

#### レンタルサーバー等で自動生成される記述がある場合
サーバーの管理画面等で自動生成されるコメントブロック（`# BEGIN ...` 〜 `# END ...`）がある場合は、そのブロックの**外側（直後）**にマーカーを配置してください。

### 4. 除外IPの解除（パージ）
* **自動解除**: 管理画面からログアウトした際、およびプラグイン管理画面から本プラグインを無効化した際に、登録されていた除外ブロックは自動的に削除されます。
* **手動リセット**: 設定画面の「WAF除外IPを全てクリア」ボタンを押すと、過去に登録されたすべての除外IPを消去し、現在ログイン中のあなたのIPアドレスのみが自動的に再登録されます。

## 動作確認（WAF除外のテスト方法）

本プラグインが正しく動作しているか（WAFが有効な状態のまま、ログイン中の管理者IPのみバイパスできているか）は、以下の無害なテスト用文字列を用いて確認できます。

> **※テスト文字列について**
> ここで使用する `<script>alert(1)</script>` や `<script>alert('WAF_TEST')</script>` は、サーバーやデータベースにダメージを与えない無害な文字列ですが、「典型的なXSS攻撃（または偵察行為）」としてWAFに標準で組み込まれている最優先でブロックするシグネチャ（検知ルール）に該当するため、WAFの動作確認に最適です。

### 1. URLパラメータで試す方法（GET送信・最も手軽）
ブラウザのアドレスバーで、サイトや管理画面の任意のURL末尾に以下のパラメータを付けてアクセスします。

```text
?test=<script>alert(1)</script>
```
* **アクセス例**: `https://example.com<script>alert(1)</script>`

### 2. 管理画面のフォーム入力で試す方法（POST送信）
ブログ記事や固定ページの編集画面で試す場合は、エディタによって自動エスケープ変換される「本文欄」ではなく、プレーンテキストとして送信される **「タイトル欄」** に以下の文字列を入力して「保存」を押します。

```html
<script>alert('WAF_TEST')</script>
```

### 判定基準（正常動作の確認）
1. **WAF除外が「無効」の状態（ログアウト中のシークレットウィンドウや別回線のスマホ等）**
   * 上記のテストを実行すると、サーバーから **`403 Forbidden`** エラーが返ります。
2. **本プラグインが「有効」の状態（対象グループでログイン中のブラウザ）**
   * まったく同じテストを実行しても403エラーにならず、**通常のページ表示（または保存完了）**が行われます。

※テストは必ずご自身が管理するサイトに対してのみ実施し、フォーム保存のテストを行った場合は確認後にテスト記事を削除（またはタイトルを元に戻）してください。

## アップデート方法と注意点

本プラグインはデータベースを使用せず、プラグイン内の `Config/setting.php` に設定値を保存する設計となっています。そのため、**新しいバージョンのファイル一式を上書きアップロードしてアップデートすると、設定内容（使用するWAF種別・対象ユーザーグループ・動作モード）が初期状態にリセットされます。**

1. 新しいバージョンの `WafExclusion` フォルダ一式を `app/Plugin/` 配下に上書きアップロードします。
2. 上書きによってファイル権限が初期化される場合があるため、`app/Plugin/WafExclusion/Config/setting.php` にWebサーバー（PHP）からの書き込み権限（`604` 等）が設定されているか確認してください。
3. アップデート後、管理画面の設定画面を開き、「使用するWAF種別」「対象ユーザーグループ」「動作モード」を再度、確認・選択・保存してください。

## 運用上の重要な注意制限（セキュリティリスク）

### Cloudflare等のCDNやプロキシサーバーを使用する場合
本プラグインは接続元IPアドレスの取得に標準的な `REMOTE_ADDR` を使用しています。
**CloudflareなどのCDNサービスやリバースプロキシをサイトの前面に導入した場合、取得されるIPアドレスがすべて「CDNサーバーのIP」になってしまいます。**

この状態でプラグインが動作すると、**不特定多数（全員のアクセス）に対してWAFの防御をバイパスしてしまう重大なセキュリティリスク** が発生します。IP復元設定（`mod_remoteip` 等）が正しく行われていないCDN・プロキシ環境では絶対に使用しないでください。

## 注意事項・免責事項

* ModSecurity選択時、サーバー側のビルド設定や `AllowOverride` の制限により `.htaccess` 内での `SecFilterEngine` / `SecRuleEngine` 記述が許可されていない環境では、書き込み時に **500 Internal Server Error** が発生する場合があります。導入前には必ず **対象となる `.htaccess` のバックアップ** を取得し、万が一500エラーが発生した場合はFTP等で `.htaccess` から `# --- WAF_EXCLUSION_START ---` 〜 `# --- WAF_EXCLUSION_END ---` のブロックを削除してください。
* 本プラグインによるWAF検査の除外対象は、管理画面にログイン中の対象ユーザーのIPアドレスのみに限定されていますが、より安全な運用を維持するため、管理画面での作業終了後はログアウトして除外設定を解除する運用を推奨します。
* プラグインをアップデート（ファイル上書き）すると、`Config/setting.php` の設定値は初期状態に戻ります。アップデート後は設定画面から再度確認してください。
* 本プラグインの利用によって生じたいかなる損害についても、作者は一切の責任を負いません。
